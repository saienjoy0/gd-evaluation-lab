# 人間評価ガイド v0.1

## 1. 対象と制限

本ガイドは、GD練習セッション中に観察された行動を評価するためのものである。

評価してよいもの:

- Episode内で観察できる発言と行動
- シナリオが提供した評価機会への反応
- 議論の前後で起きた具体的な変化

評価してはいけないもの:

- 性格、外向性、将来のリーダー性
- 年齢、性別、障害、出身、アクセント等の推定
- 声の高さ、視線、顔つきによる能力推定
- 発言量だけを根拠にした高低評価
- AI側の失敗を利用者の低得点として扱うこと

本評価は練習・研究・shadow evaluation用であり、採用合否の自動決定には使用しない。

## 2. 評価前の確認

評価者は次を確認する。

1. AIが出した利用者スコアが非表示である
2. EpisodeのSchema検査が成功している
3. System Quality Gateの結果が提示されている
4. 評価対象の匿名participant_idが明示されている
5. Scenarioのevaluation opportunityが確認できる
6. 使用するrubric_versionとcalibration_set_versionが明示されている

いずれかが欠ける場合は、評価開始前にデータ不備として記録する。

## 3. 証拠先行の評価手順

各サブディメンションについて、必ず次の順番で評価する。

### Step 1: 評価機会を判定する

- `sufficient`: 能力を示す機会が十分あった
- `insufficient`: 機会がなく、点数評価できない
- `uncertain`: 機会の有無を一意に判断できない

評価機会とは、利用者が行動を選べる具体的な場面である。他者が全て処理済みの場面を、利用者の未行動として数えない。

### Step 2: 証拠発言を選ぶ

点数を考える前に、利用者本人の`message_id`を選ぶ。

証拠として適切なもの:

- 評価質問に直接関係する
- 文脈を含めて意味が確認できる
- 利用者本人の発言である
- その行動による議論上の変化を説明できる

証拠として不適切なもの:

- AIや別参加者の発言
- 単なる挨拶や相づち
- 文脈を切り取ると意味が変わる発言
- 点数に合うよう都合よく選んだ一部分

### Step 3: BARSアンカーへ照合する

| 点数 | 判断 |
|---|---|
| 1 | 期待行動が見られない、または議論を妨げる観察行動がある |
| 2 | 一部は見られるが、表面的・不完全・不安定 |
| 3 | 期待行動が明確に観察され、議論へ有効に作用 |
| 4 | 複数場面で高度な行動が観察され、チーム全体を改善 |
| NE | 機会不足、AI品質不良、ログ不良、証拠不足等で評価不能 |

1点は「能力が低い人物」という意味ではない。そのEpisodeで、十分な機会がありながら期待行動が観察されない、または妨害行動が観察されたという意味に限定する。

### Step 4: 点数またはNEを記録する

数値評価:

- 最低1件の実在する利用者発言IDが必要
- 4点は異なる時点の独立証拠を2件以上必要
- `not_evaluable_reason`はnullにする

NE評価:

- 証拠発言は空にする
- `not_evaluable_reason`を必須にする
- 低信頼だからという理由だけでNEにせず、何が不足したかを示す

### Step 5: 自信度と注記を記録する

自信度は0〜1で記録する。

- 0.80以上: アンカーと証拠が明確
- 0.60〜0.79: 妥当だが代替解釈がある
- 0.60未満: 人間レビューまたは調停を優先

## 4. NE理由

| コード | 使用条件 |
|---|---|
| `INSUFFICIENT_OPPORTUNITY` | シナリオが行動機会を提供しなかった |
| `AI_QUALITY_FAILURE` | AI・進行不良により行動機会や文脈が壊れた |
| `TRANSCRIPT_INCOMPLETE` | 欠損やSTT不良で判断できない |
| `INSUFFICIENT_EVIDENCE` | 機会はある可能性があるが、採点に足る観察証拠がない |
| `JUDGE_FAILURE` | 自動評価工程の失敗を記録する場合。人間単独評価では通常使わない |
| `SCENARIO_CONTRACT_FAILURE` | Scenario定義と実行が一致せず機会判定不能 |
| `OTHER_REVIEW_REQUIRED` | 上記で表現できず、理由を自由記述する必要がある |

## 5. 7サブディメンションの観察観点

### 課題設定・論点形成

- 目的、対象、成功条件を明確にしたか
- 前提、制約、不足情報を整理したか
- 議論すべき論点を構造化したか
- 判断基準を提案したか

### 論理的思考・根拠

- 主張と理由を接続したか
- 根拠、具体例、比較を使ったか
- 前提や条件を明示したか
- 反証、不確実性、弱点を扱ったか

### 傾聴・応答

- 他者の主張を正確に捉えたか
- 質問や懸念に直接応答したか
- 他者意見を踏まえて案を修正したか
- 複数意見を関連付けたか
- 対立点や誤解を明確にしたか

### 価値ある貢献

- 新しい視点または具体案を提供したか
- 議論の状態を前進させたか
- 既存案を改善・統合したか
- 重要なリスク・見落としを補ったか

### 協働・関係構築

- 他者が参加しやすい働きかけをしたか
- 意見差を人格ではなく論点として扱ったか
- 発言機会の偏りを調整したか
- 建設的反論と心理的安全性を両立したか

### 意思決定・合意形成

- 複数案を判断基準で比較したか
- 選択理由を明示したか
- 反対・少数意見を処理したか
- 実行条件、リスク、弱点を含む合意を作ったか

### 時間・議論プロセス管理

- 残り時間と進捗を把握したか
- 次の論点、行動、時間配分を具体化したか
- 停滞・脱線を検知して修正したか
- 理解を保ちながら収束方法を再設計したか

## 6. 二重評価と調停

独立評価者は互いの点数・コメントを見ずに評価する。

調停対象:

- 2点以上の差
- 数値とNEの不一致
- 証拠発言が一致しない
- opportunity_statusが一致しない
- いずれかのconfidenceが0.60未満

調停者は、多数決で決めず次の順で原因を分類する。

1. 評価機会の解釈差
2. 証拠範囲の解釈差
3. BARSアンカーの曖昧さ
4. シナリオまたはログの欠陥
5. 評価者手順の逸脱

ルーブリック自体に問題がある場合は、Episodeの最終点だけを直して終わらせず、`rubric_issue_code`を残す。

## 7. 評価者校正

本番評価前に次を行う。

- 35マイクロアンカーを採点
- 12完全Episodeを独立採点
- 不一致を調停
- NEと1点、3点と4点の境界を説明
- 校正セットの版をrater sheetへ保存

校正未完了の評価者による結果は、研究用仮注釈として区別する。

## 8. 禁止事項

- AI評価を見てから人間点を合わせる
- 証拠を選ぶ前に総合印象で点数を決める
- 3領域の印象から7軸を逆算する
- 一つの発言だけで全軸を採点する
- 機会不足を1点にする
- 長く話したことを高得点の直接根拠にする
