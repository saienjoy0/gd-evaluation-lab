# GD評価 検証計画 v0.1

## 1. 目的

本計画は、GD評価システムが「練習・育成用途で説明可能な評価」として使用できるかを段階的に検証する。

検証対象は、評価点の見栄えではなく次の四点である。

1. 技術的に壊れていないこと
2. 同じ行動を一貫して評価できること
3. 意図したGD行動を測れていること
4. 表現上の差やAI側の不備を利用者能力と誤認しないこと

本計画の合格は、採用合否への使用許可を意味しない。

## 2. 検証単位

| 単位 | 主な確認事項 |
|---|---|
| Scenario | 評価機会、役割、制約、required/forbidden moveが明確か |
| Episode | ID、時刻、参加者、発言、イベント、版情報が整合しているか |
| SystemQualityResult | AI・システム側の不良を検出できるか |
| Human Rater Sheet | 証拠先行で同じ手順を再現できるか |
| Question/Dimension Evaluation | 実在する利用者発言に基づくか |
| Adjudication Record | 不一致の理由と最終判断を追跡できるか |
| Competency Summary | 3領域の説明が7軸の証拠と矛盾しないか |

## 3. 段階

### Phase A: 契約・合成データ検証

対象:

- JSON Schema
- 意味整合性検査
- 35マイクロアンカー仕様
- 12完全Episode仕様
- 合成fixture

完了条件:

- 全正例がSchemaと意味検査を通る
- 全負例が意図した理由で失敗する
- 証拠ID、発言者、時刻、版情報の不整合をCIで検出できる

### Phase B: 評価者校正リハーサル

対象:

- 35マイクロアンカー
- 12完全Episode
- 2名以上の独立評価者

手順:

1. AIスコアを非表示にする
2. 証拠発言を先に選ぶ
3. BARSアンカーに照合する
4. 1〜4またはNEを付ける
5. 自信度を記録する
6. 評価差を調停する

完了条件:

- NEと1点の境界を評価者が説明できる
- 4点に複数場面の独立証拠がある
- 不一致がアンカー不足、機会判定、証拠解釈のどれかに分類される

### Phase C: 匿名100セッション・初期パイロット

対象:

- 同意済み・匿名化済みの実セッション
- 旧評価
- 新評価
- AI品質結果

確認事項:

- 評価機会数とNE率
- Judge失敗率
- 旧評価との不一致
- 発言量と評価点の相関
- 証拠説明の妥当性

### Phase D: 100〜300セッション・二重評価

対象:

- 人間評価者2名の独立評価
- 調停済み基準値
- LLM Judge複数回評価
- 公平性ペア

確認事項:

- human-human一致
- LLM-human一致
- 同一Judge再採点安定性
- シナリオ別・軸別の偏り
- 名前、文体、長さ、発言順、STT誤りへの感度

## 4. 指標

### 4.1 技術完全性

- Schema適合率
- ID参照整合率
- 時刻整合率
- 証拠ID実在率
- 証拠話者整合率
- 必須版情報充足率
- Judge失敗率
- 再実行可能率

### 4.2 信頼性

- 同一Judge・同一Episodeの再採点一致
- 異なるJudge間の一致
- 人間評価者間のweighted kappa
- Krippendorff's alpha
- 必要に応じたICC
- LLMと調停済み人間評価のMAE
- 1点以内一致率
- 軸別混同行列

### 4.3 妥当性

- 各演習が意図した評価機会を提供した割合
- 評価機会がある場合のNE率
- 7軸間の相関と重複
- 難易度別の行動出現差
- 発言量・発言時間と能力点の過剰相関
- 旧評価と新評価の差の説明可能率

### 4.4 公平性・頑健性

次の意味内容を維持したペアを比較する。

- 名前のみ変更
- 丁寧語と簡潔語
- 長文と短文
- 発言順の入替
- 軽微なSTT誤り
- 同一内容でフィラー有無

各ペアは、意味的能力差がない前提で点差と証拠選択差を測る。

## 5. 暫定リリースゲート

以下は外部標準ではなく、本プロジェクトの暫定値である。パイロット後に改訂する。

| 指標 | 暫定ゲート |
|---|---:|
| 契約・証拠ID検査 | 100%成功 |
| 重大な決定論的違反の見逃し | 0件 |
| 同一ログ再採点の1点以内一致 | 95%以上 |
| 人間評価者間weighted kappa | 各軸0.60以上、0.70以上を目標 |
| LLMと調停済み人間評価の1点以内一致 | 85%以上 |
| Judge失敗率 | 2%未満 |
| 公平性ペアの平均差 | 0.25点未満 |
| 1点以上変化した公平性ペア | 全件レビュー |
| 証拠が説明と対応しないケース | 2%未満 |

## 6. リリース判定

### v0.x継続

次のいずれかがある場合は正式表示しない。

- 評価機会と利用者未行動を区別できない
- AI品質不良を利用者低得点にしている
- 実在しない証拠IDを許容する
- NEと1点の判断が評価者間で安定しない
- 特定軸で人間評価者間一致が0.60未満
- 公平性ペアで説明できない大差が継続する

### v1.0候補

- 3標準演習が運用可能
- System Quality Gateが先に動く
- 7軸が証拠付きで評価される
- 3領域フィードバックが人格断定を含まない
- 人間校正、再現性、公平性の結果が版管理される

## 8. 変更管理

ルーブリック、アンカー、シナリオ、Judge、集約規則の変更は別々に版を上げる。

結果差が出た場合に「会話が変わったのか」「Judgeが変わったのか」「集約規則が変わったのか」を追跡できない変更は受け入れない。
