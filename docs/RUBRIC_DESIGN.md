# ルーブリック設計 v0.1

## 1. 採点尺度

利用者行動は各軸を`1`〜`4`または`NE`で評価する。

| 値 | 意味 |
|---|---|
| 1 | 期待される行動が見られない、または議論を妨げる行動がある |
| 2 | 一部は見られるが、表面的・不完全・不安定である |
| 3 | 期待される行動が明確に観察され、議論へ有効に作用する |
| 4 | 複数場面で高度な行動が観察され、チーム全体の議論を改善する |
| NE | 評価機会不足、ログ不良、AI品質不良などで評価不能 |

## 2. 証拠ルール

- スコア1〜3には最低1件の実在する`message_id`を要求する。
- スコア4には原則2件以上の独立した証拠を要求する。
- `NE`では`not_evaluable_reason`を必須とする。
- AI品質ゲートが特定軸へ影響した場合、その軸はJudgeで推測しない。
- Judgeが返した`message_id`はエピソード内に存在するか検証する。
- 別参加者の発言を利用者の証拠として使用しない。

## 3. 小質問方式

7軸を直接総合印象で採点せず、各軸を4〜5個の観察質問へ分解する。

各質問は次の確率分布を返す。

```json
{
  "not_observed": 0.05,
  "partially_observed": 0.15,
  "observed": 0.65,
  "strongly_observed": 0.15
}
```

v0.1ではルールベースで分布を1〜4へ集約する。人間評価データが蓄積した後、校正モデルの導入を検討する。

## 4. AI品質ゲート

利用者評価の前に、次の順でGD環境を検査する。

1. JSON Schema検証
2. 決定論的ルール
3. シナリオ固有ルーブリック
4. AI参加者8軸Judge
5. 評価機会の確認
6. 利用者7軸Judge
7. 証拠整合性検証

## 5. 決定論的に扱う項目

- ユーザー発話中のAI確定発言
- stale generationの確定・未破棄
- AI連続発言数
- 同一AIの過剰連続
- 禁止されたphase遷移
- required moveの欠落
- forbidden moveの実行
- ログ欠損
- 発言ID重複
- 終了前の必須段階未完了

## 6. LLM Judgeが扱う項目

- 論点形成の質
- 根拠と主張の接続
- 他者発言への意味的応答
- 提案の新規性・改善性
- 建設的な対立処理
- 合意形成の質
- 進行調整の妥当性

## 7. 人間レビュー条件

- Judgeの`confidence < 0.6`
- 同一ログの再採点差が2点以上
- 複数Judge間で2点以上の差
- 証拠検証失敗
- 新しいシナリオまたはルーブリック版
- 利用者からの異議
- 研究用ランダムサンプル

## 8. shadow mode

新評価v0.1は、旧評価を直ちに置き換えない。

保存項目:

- `legacy_evaluation`
- `candidate_evaluation_v0_1`
- `ai_quality_result`
- `evaluation_disagreement`
- `review_status`

旧評価と新評価の差を分析してから、表示切替を判断する。
